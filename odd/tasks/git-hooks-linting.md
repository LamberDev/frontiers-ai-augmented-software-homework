# Feature: git-hooks-linting

## Objective
Pre-commit hook (Lefthook) plus formatting/linting for both apps: ESLint + Prettier in
`apps/web`, `dotnet format` (whitespace + style) in `apps/api`, driven by the root `.editorconfig`.

## Why
Keep formatting and style consistent automatically, only on staged files, without slowing commits.

## Scope
- In: root private `package.json` (lefthook devDependency, `prepare`), `lefthook.yml`,
  Prettier + `eslint-config-prettier` in `apps/web` (`.prettierrc`, `.prettierignore`,
  `format`/`format:check`), C# style rules in `.editorconfig` (severity `warning`),
  README "Git hooks" section.
- Out: CI pipeline (T5, delivered by feature `ci-workflow`), `dotnet format style` in the hook, analyzers in the hook (already enforced by `TreatWarningsAsErrors` on build).

## Constraints
- Per-app `root` + `glob`, `{staged_files}` only, parallel, `stage_fixed: true`.
- `{staged_files}` are relative to each command's `root`; `dotnet format --include` must receive
  paths that resolve correctly against `PeerReview.slnx`.
- No commit without explicit user consent (overrides ODD auto-commit).
- Leave the repository clean after the tests (no test files or commits).

## Acceptance criteria / checks
1. `pnpm install` at root installs hooks (`.git/hooks/pre-commit` generated by Lefthook).
2. Misformatted staged `.vue`/`.ts` is auto-formatted and the commit completes.
3. A non-autofixable ESLint error in `apps/web` fails the commit.
4. Misformatted staged `.cs` (bad indentation, block namespace) is fixed and the commit completes.
5. Web-only commit does not run `dotnet format`; api-only commit does not run ESLint/Prettier
   (Lefthook output shown).
6. Hook duration with a single staged `.cs`; if > 10 s, stop and ask about moving
   `dotnet format style` to CI.
7. Repository left clean (no test files, no test commits).
